# Chrome 图片上传兼容性需求

## 范围

修复 Chrome 等浏览器选择、粘贴或拖拽图片时因 `File.type` 为空或不标准而出现“请选择图片文件”的问题。三个入口必须使用同一套安全图片识别逻辑。

## 已确认事实

- `frontend/js/app.js` 的文件选择、粘贴、拖拽入口都直接检查 `file.type.startsWith('image/')`。
- 文件选择的 `change` 处理器先保存活的 `input.files`（FileList），再把 `input.value` 清空；清空会同时清空该 FileList，后续读取到空列表，直接显示“请选择图片文件”。
- Chrome 对部分本地图片也可能返回空 MIME；即使先修复 FileList 时序，单用 `file.type` 仍会丢弃这些有效图片。
- 后端改图路由会读取上传字节并自行识别图片类型；前端需要先正确读取并生成 data URL。

## 验收标准

- 标准 MIME 图片可继续上传。
- MIME 为空但文件头为 PNG/JPEG/WebP 的图片可上传。
- 伪装成图片扩展名但文件内容不是图片的文件会被拒绝。
- 文件选择、粘贴、拖拽使用同一识别函数。
- HEIC/HEIF/AVIF/GIF/SVG 等当前上传链路无法一致处理的格式显示明确转换提示。
- 自动化测试、语法检查和两轮真实浏览器/HTTP 验证如实记录。

## 排除项

不改变上游图像接口、不把原始文件上传到服务器、不保存 API Key，不自动部署生产。
